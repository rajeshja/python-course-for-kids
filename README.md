# Learn to Code by Drawing and Playing — Student Lessons

Welcome! These 29 lessons teach Python by letting you **draw, experiment, make games, and solve puzzles**.

This version is designed so that an 11-year-old who has never programmed before can work with **minimal adult help**.

## How to work through a lesson by yourself

Use this routine every time:

1. **Read the goal.**
2. **Get the starting code** from the lesson or starter file.
3. **Save the file with the exact name shown.**
4. **Run the complete example before changing it.**
5. **Predict on paper** what you think will happen.
6. **Change exactly one thing.**
7. **Run it again and compare the result with your prediction.**
8. **Build the Core Challenge one checkpoint at a time.**
9. **Do the Bug Hunt as an exercise:** predict → run → find the clue → fix → run again → explain.
10. **Check your work.**
11. **Only then use the answer key.** Start with Hint 1. Do not copy the worked example until you have tried the earlier hints.

You do **not** need to understand every line before you run a complete example. First make it work. Then learn what each part does.

## Where to type and run code

- Sessions **1–12** use Python's Turtle module. Each lesson tells you the file name to create. Run it with Python.
- Sessions **13–21** use **Pygame Zero**. Session 13 contains the setup instructions and the rest of these lessons use the same setup.
- Sessions **22–29** use **plain pygame in VS Code**. Session 22 contains the complete setup and installation walkthrough.

If you are already using the course's supplied starter project, use the folder and run instructions in the lesson instead of creating a second project.

## One important rule

**You are allowed to make mistakes.** In programming, mistakes are useful clues. You do not need another person beside you to try the next step.

When you are stuck, first write:
- **I expected:** ...
- **I saw:** ...
- **The line I think is involved:** ...
- **The one thing I changed:** ...

Then use the lesson's recovery hints and answer key.

## A useful habit: paper first

Keep a sheet of paper beside your computer. Before you run code, predict what will happen.

For Turtle programs, sketch the turtle, its direction, and the path you expect. For drawing projects, sketch the screen and the shape positions. For games, sketch the screen, objects, controls, or a short sequence of game states. For debugging, write down what you expected and what actually happened.

Your prediction does not need to be correct. Making a prediction and then comparing it with the computer's result is one of the best ways to learn programming.

## If you are working alone

Some older versions of these lessons mentioned a partner, team, game fair, or presentation. You never need another person to finish a lesson.

When a lesson says to show your work to someone else, use the **Solo option** in that lesson: record a short demo, write the reflection answers, and run the self-check.

## Answer keys

Each answer key contains:
- the answer to the thinking questions;
- **Hint 1** — a small clue;
- **Hint 2** — the next concrete step;
- a **worked example or rescue path**;
- a short explanation of why it works.

Try the lesson first. Use the hints in order. The worked example is a rescue tool, not the starting point.

## You can always stop at the minimum

Every Core Challenge has a **minimum success condition**. Finish that first. Stretch and Bonus challenges are optional.

A small program that works is a success.
